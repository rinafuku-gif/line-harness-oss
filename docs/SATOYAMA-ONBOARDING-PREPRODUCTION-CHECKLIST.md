# SATOYAMA LINEオンボーディング 本番前チェックリスト

確認日: 2026年7月27日
状態: D1 migration、Worker配置、feature有効化まで完了。一般向け入口と実機テストは未完了

## 1. 現時点の推奨判断

初回公開は、機能を小さく開く。

- 友だち追加直後に画面を強制表示せず、挨拶メッセージ内の明示ボタンから開く。
- 公開LIFFの実効scopeは既存設定の `openid profile` である。このオンボーディング実装は
  `profile` を使わず、`chat_message.write`も追加しない。
- `chat_message.write` は初回公開では付けず、相談文をコピーしてLINEトークへ戻る方式から始める。
- 48時間後の再案内は停止したまま公開し、少人数確認後に別判断する。
- AIニュースは一斉配信せず、リッチメニュー等から読むプル型を維持する。
- 質問は任意とし、未回答でもAI相談、リッチメニュー、診断、予約を利用できる状態を保つ。

この形なら、権限、外部送信、配信負荷を増やさずに、3問の完了率と案内の分かりやすさを
先に検証できる。

## 2. LIFF画面で回答前に表示する短い説明文案

> 回答は任意です。選択内容とLINE上の識別子を、案内の個別化、相談受付、
> サービス改善のために保存します。回答しなくても、AI相談やメニューは利用できます。
> 詳しくはプライバシーポリシーをご確認ください。

表示要件:

- 1問目より前、または1問目の上部に表示する。
- 「プライバシーポリシー」は `https://www.satoyama-ai-base.com/legal/privacy` へリンクする。
- 画面を閉じる導線と「今回は回答しない」を、回答ボタンと同じ画面内に残す。
- 「同意しないとLINEを使えない」と受け取られる表現を使わない。

個人情報保護委員会は、Web入力画面等で本人から直接個人情報を取得する場合、
原則として利用目的をあらかじめ明示する必要があると案内している。LINEの認可画面とは別に、
このオンボーディングで何を保存し、何に使うかを画面上で説明する。

## 3. サイトのプライバシーポリシー追記案

`/Users/Inaryo/satoyama-ai-base/shared/legalPagesData.ts` が法務ページ本文の正本である。
公開サイトには、オンボーディングに必要な収集項目、利用目的、保存期間、削除方針が
反映済みであることを2026年7月27日に確認した。

### 「収集する情報」への追記案

- LINE公式アカウントおよびLINE連携機能を利用した場合、LINE上のユーザー識別子、
  友だち状態、オンボーディングで選択した立場・課題・業務領域を取得します。
- 特典の表示、質問の開始・完了・スキップ、相談導線の選択、再案内の実施状況について、
  操作日時と状態を取得します。
- オンボーディングでは自由記述の回答を収集しません。相談機能を利用した場合の会話内容は、
  別途、相談対応と会話継続のために保存されます。

### 「情報の使用目的」への追記案

- 利用者の状況に近い事例、特典、ワークショップ、相談方法を案内するため
- LINE上での相談受付と、利用者が明示的に選んだ次の行動を支援するため
- 質問の負荷、特典の利用状況、導線の分かりやすさを集計し、サービスを改善するため
- 有効化した場合に限り、未回答者へ最大1回の再案内を行うため

### 「外部サービスの利用」への追記案

- LINEヤフー株式会社のLINE公式アカウント、LINEログイン、LIFFおよびMessaging APIを、
  本人確認、画面表示、メッセージの受送信に利用します。
- Cloudflare, Inc. のWorkersおよびD1を、オンボーディング機能の提供と回答状態の保存に
  利用します。
- 各サービスでの情報の取扱いは、各社の規約・プライバシーポリシーも適用されます。

「国内だけに保存される」とは記載しない。Cloudflare D1は、作成時の条件によって
データ配置が決まり、既存本番DBの実測位置は未確認である。公開前に契約、D1設定、
データ移転に関する説明の要否を確認する。

### 「保存期間・削除」への追記案

次は法令上の一律基準ではなく、データ最小化を優先して採用した初期運用値である。

| データ | 初期運用案 |
|---|---|
| 回答イベント履歴 | 90日後に削除 |
| 最新の3回答と14タグ | 友だち期間中は保持。ブロック・友だち解除後30日で削除 |
| 特典・CTA・再案内の操作時刻 | 90日後に削除 |
| 認証・障害調査ログ | 個人識別子を原則出さず、30日を目安に削除 |
| 明示的な相談・予約記録 | オンボーディングとは分け、契約・問い合わせ対応に必要な期間を別途定める |

対象accountだけに働く自動削除処理を実装し、他account、通常metadata、`[SB]`以外のタグを
保持するテストを追加した。本番公開時はD1バックアップを確認し、
`SATOYAMA_ONBOARDING_RETENTION_ENABLED=true`を質問導線より先に有効化する。

### 「利用者の選択と問い合わせ」への追記案

- 3問への回答は任意であり、回答しなくてもLINEの基本機能を利用できます。
- 回答は後から変更できます。
- 配信停止はLINE上のブロック・友だち解除で行えます。
- 保存情報の開示、訂正、削除を希望する場合は、SATOYAMA AI BASEの問い合わせ窓口から
  連絡できます。

### Stage 1: コードを閉じたまま配置

1. D1 migration対象を明示し、適用前後のschemaを記録する。
2. Workerコードを `SATOYAMA_ONBOARDING_ENABLED=false`、
   `SATOYAMA_ONBOARDING_REMINDER_ENABLED=false`、
   `SATOYAMA_ONBOARDING_RETENTION_ENABLED=false` のまま配置する。
3. LIFFを配置し、一般ユーザー向け導線にはまだ接続しない。
4. APIがflag off時に404で閉じることを確認する。

実施結果:

- migration 047を本番D1へ適用した。
- feature停止時のWorker version
  `9e8b389d-1587-41a6-b75f-02881ee26f83`でAPI 404を確認した。
- 公開LIFF画面は現行Workerと同一originから配信した。
- リッチメニューv13と一般向け導線は変更していない。

### Stage 2: 内部テスト

1. 対象SATOYAMA accountだけを設定する。
2. テスト用ユーザーだけが開ける明示URLから、質問、スキップ、再回答を確認する。
3. 別accountのIDトークン、未follow、期限切れ・不正トークンが拒否されることを確認する。
4. 14タグ以外の既存タグが再回答後も残ることを確認する。
5. AI相談、予約、リッチメニュー、既存webhookが従来どおり動くことを確認する。
6. 外部送信を伴わないコピーCTAから始める。
7. D1バックアップ後、Retentionだけを有効にして削除対象件数とaccount境界を確認する。

実施済み:

- 対象accountを固定し、Retentionを有効化した。リマインダーは停止したままである。
- 認証なし・不正Bearerは401、別LIFF IDは404になることを本番APIで確認した。
- 回答状態・回答イベント・再案内予定がすべて0件であることを確認した。
- 公開LIFF URLがLINE Loginへ到達し、`chat_message.write`を要求しないことを確認した。

未実施:

- テスト用LINEユーザーによる3問回答、スキップ、再回答
- 14タグの本番保存と、既存タグが残ることの実測
- 実機でのコピーCTA、ブロック・友だち解除後の取消と30日削除
- 既存AI相談、予約を同じテストユーザーで通す回帰確認

### Stage 3: 少人数公開

- 挨拶メッセージまたはリッチメニューに、本人が押すオンボーディングボタンを追加する。
- 48時間後再案内は停止したままにする。
- 7日間または20完了の早い方まで、開始率、完了率、スキップ率、エラー率を観察する。
- 完了率だけで良し悪しを決めず、回答後に次の一歩が理解できるかを確認する。

現状はfeatureを有効化したが、挨拶メッセージとリッチメニューに入口を追加していない。
一般向けの少人数公開はまだ開始していない。

停止基準:

- 認証・account境界の異常が1件でも発生
- 既存AI相談、予約、webhookに回帰が発生
- 送信していないはずのLINEメッセージが送られる
- 連続した5xx、タグ消失、重複保存が再現

停止時は2つのfeature flagを `false` にし、外部導線を直前の状態へ戻す。
追加型migrationのtableは緊急時に削除しない。

### Stage 4: 再案内・送信権限の別判断

少人数公開の結果を確認してから、次を別々に判断する。

- 48時間後の最大1回案内を有効にするか
- `chat_message.write` を付けて、明示CTAから相談文をLINEトークへ送るか
- 課題別配信を月2回から始めるか

3つを同時に有効化しない。問題が起きた時に原因を切り分けられる順番で1つずつ開く。
